Install Backstage on a Raspberry Pi

This guide uses Raspberry Pi OS with Desktop, 64-bit on a Pi 4 or Pi 5, with a screen, keyboard and mouse attached for the first setup. The package includes its runtime and starts Backstage automatically after every reboot.

For your existing FOH Pi: do not re-image its current card. That would erase Companion Satellite and its setup. Back up the card with your production lead first. If you are unsure of the operating system, test on a spare microSD card or a spare Pi. The installer does not change Companion Satellite or Dicaffeine, but shared CPU, memory and network use must be tested before a service.

Before you begin

  • Pi 4/5 with a suitable power supply, Ethernet connection preferred, screen, keyboard and mouse.
  • A working 64-bit Raspberry Pi OS desktop (Bookworm/Debian 12 or newer recommended). A 64-bit kernel alone is not enough; the installed OS must be arm64.
  • For a fresh card, use a spare 32 GB or larger microSD card and a card reader.
  • Your Pi login password and access to the public GitHub preview release, or a USB drive with the package and this guide.

1. Prepare the Pi

If the Pi already has a working desktop

Skip to step 2. Do not write an OS image over its existing card. A 32-bit installation cannot use this package; use a separate 64-bit test card rather than replacing the production card.

If you are using a fresh, spare card

  1. On your PC, install Raspberry Pi Imager.
  2. Choose your Pi model, then Raspberry Pi OS with Desktop (64-bit). Do not choose Lite for this beginner setup.
  3. Choose the spare microSD card. Check its name and size carefully: writing erases the selected card.
  4. In the customization screens, choose a username and password you can remember. Set a unique hostname, such as backstage-test. Configure Wi-Fi if you cannot use Ethernet.
  5. Write and verify the card. Eject it, insert it into the Pi, attach the screen/keyboard/mouse and network, then turn it on.
  6. Complete the desktop welcome steps and any offered OS updates. Restart if requested.

The official Raspberry Pi getting-started guide explains Imager and first boot. The Raspberry Pi OS guide covers OS editions and package installation.

2. Download and install Backstage

  1. On the Pi, open the browser. No GitHub account or invitation is needed.
  2. Open the preview release. Under Assets, download backstage-production_0.1.1-preview4_arm64.deb into Downloads. Do not download “Source code.” A copy on a USB drive also works.
  3. Open File Manager, go to Downloads and double-click the .deb file.
  4. If the desktop opens a package installer, choose Install and enter your Pi password when asked. Wait for it to finish.
If double-clicking opens an archive or no installer: the desktop’s package helper is missing. Close the archive. Click the Terminal icon and copy/paste this single installation command, then press Enter. This is the standard Raspberry Pi package installer; you do not need to write code or edit configuration files. Keep the downloaded filename exactly as shown.
sudo apt install ~/Downloads/backstage-production_0.1.1-preview4_arm64.deb

Enter the Pi password if asked; it is normal for no password characters to appear. If asked to continue, type Y and press Enter. Wait for “Backstage is ready,” then close Terminal. Internet may be needed for missing operating-system dependencies.

3. Create the first PIN on the Pi

  1. In the Pi’s browser, type http://127.0.0.1:3100 in the address bar. You can also use Open Backstage in the desktop’s Internet/Network application menu.
  2. Create a shared 6–12 digit numeric PIN and repeat it. Do this on the Pi itself; the first PIN cannot be created from your laptop.
  3. Add a test musician and equipment, assign them in Service lineup, and publish the musician.
  4. Open http://127.0.0.1:3100/display in another browser tab to check the result.

The installer starts the host automatically. You can close the browser and log out; the service remains running. It also starts after power-on. Always use the Pi desktop’s Shutdown command before unplugging power.

4. Connect FOH and backstage over the network

  1. Find the Pi’s IP address in the desktop’s network connection information (click or hover over the Wi-Fi/Ethernet icon). It usually looks like 192.168.x.x or 10.x.x.x. Your network volunteer can identify it in the router’s device list.
  2. On an FOH computer connected to the same network, open http://PI-IP:3100, replacing PI-IP with that address. For a fresh card named backstage-test, http://backstage-test.local:3100 may also work; use the numeric IP if it does not.
  3. Unlock with the PIN you created on the Pi.
  4. Use the display addresses below. Do not use 127.0.0.1 on another computer: that points to that computer, not the Pi.
  5. Ask the network lead to reserve the Pi’s IP in DHCP so these addresses stay stable. If a firewall is configured, ask them to allow TCP port 3100 only on the trusted production network.

5. Test before using it in a service

  1. Publish and update a musician from the FOH computer. Confirm the backstage screen updates.
  2. Try 14 musicians, several assignments, and hidden fixed drum inputs. Check readability from the actual viewing distance.
  3. Restart the Pi through its desktop menu. Give it a minute, then reload FOH. Verify Backstage starts and keeps the test data.
  4. Test Companion Satellite at the same time. Confirm controls remain responsive. Monitor CPU and memory using the Pi’s task manager.
  5. For a brief host/network interruption, confirm an already-open backstage page retains its last lineup. Reloading during an outage is not guaranteed on plain HTTP.
  6. Only after this passes, arrange a supervised rehearsal trial. Keep your existing production workflow available.

Data, updates and stopping

This package starts with an empty database. It does not pull church data from GitHub. Planning Center is optional and must be connected separately in the app with an approved Personal Access Token.

Before an update, use Display & connections → Export backup. Then install the newer .deb file. The app briefly restarts and keeps its data in /var/lib/backstage-production. Program files live in /opt/backstage-production. The JSON backup excludes the PIN and Planning Center credentials; a complete private host backup must also preserve the data folder and its encryption key.

For normal shutdown use the Pi’s desktop Shutdown menu. For maintenance without shutting down Companion, a production lead can use the following command to stop only Backstage:

sudo systemctl stop backstage-production

Start it again with:

sudo systemctl start backstage-production

Pi has no desktop or is used remotelyThis beginner guide assumes an attached desktop. A lead can install the same package and run the bundled set-pin script from a terminal using the service account. Do not change first-PIN protections.
systemctl status backstage-production --no-pager
journalctl -u backstage-production -n 40 --no-pager

For a headless install only, the production lead can stop Backstage, set its PIN interactively, and restart it:

sudo systemctl stop backstage-production
sudo -u backstage-production env BACKSTAGE_DATA_DIR=/var/lib/backstage-production /opt/backstage-production/runtime/bin/node /opt/backstage-production/scripts/set-pin.mjs
sudo systemctl start backstage-production

Scope: Pi 4/5, 64-bit Raspberry Pi OS and systemd. Windows uses its separate installer. Mac and 32-bit Pi packages are not included in this preview.

Finding the right network link

After unlocking FOH, look under Church network at the bottom of the sidebar. The host’s current IP and app port are shown with a copy button. Open Network addresses for display and overlay links. Share the app link (normally port 3100), not the local development preview on port 5173. Addresses refresh when the host’s network changes.

Importing a backup

  1. Open Display & connections → Import backup and choose a Backstage JSON export (up to 100 MB).
  2. Review the current and backup counts. The preview also names the service that will appear backstage.
  3. Check Replace the current saved setup and live lineup with this backup, then click Replace setup from backup. Do this outside a live service.
  4. Your current host PIN and Planning Center connection stay in place. The imported setup replaces profiles, photos, inventory, fixed setups, services and the live lineup.
  5. After success, download the offered safety backup of the previous setup and keep it somewhere private. Import that file to undo the restore. A copy also stays under backups inside the host data folder.

If the app says the setup changed after the preview, choose the file again and review the new counts before restoring. Import replaces data; it does not merge two setups.

Checking for new versions

  1. In Backstage, open Display & connections → App updates.
  2. Updates are ready to use without a GitHub account or token.
  3. The host checks at startup and every six hours. You can also click Check for updates. Preview installations include newer previews; stable installations check stable releases.
  4. When an update appears, download a data backup, then choose Download verified update. The app chooses the host’s Windows or Pi installer and checks its SHA-256 before supplying it.
  5. Open the downloaded .deb on the host Pi and choose Install. If you downloaded through a laptop, transfer it to the Pi first. Use the installation-command fallback above if the Pi has no graphical package installer, substituting the new filename. The app restarts and retains your data. Do this outside a live service.

You can also use Browse public downloads and install the new package manually. The app does not automatically run an installer or restart during a service. If an older version asks for a GitHub token, install this public package once to switch to account-free updates. Your saved data is retained.
