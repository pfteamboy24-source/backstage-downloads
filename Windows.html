Install Backstage on Windows

A click-to-install preview for a Windows 10 or 11 computer with a 64-bit Intel or AMD processor. Everything needed to run the app is included. No Node.js install, Git, commands, or PowerShell are required.

Starts empty. This installer contains no church equipment, people, pictures, PIN, or Planning Center credentials. Your test data stays on this computer. It does not sync back to James’s installation.

1. Download the installer

  1. No GitHub account or invitation is needed.
  2. Open the Backstage preview release.
  3. Under Assets, click Backstage-Setup-0.1.1-preview.6-Windows-x64.exe. Do not choose “Source code.” James can also send you this installer directly.

2. Install

  1. Open Downloads and double-click the installer.
  2. This internal preview is not digitally signed. If Windows shows “Windows protected your PC,” verify that this is the exact installer from the Backstage public download release. Only then use More info → Run anyway, if available. If your computer’s policy blocks it, ask your administrator; do not disable antivirus.
  3. Choose OK to install for your Windows account. A Backstage shortcut appears on your desktop and in Start.
  4. The Backstage control window opens and starts the app. A browser opens at http://127.0.0.1:3100.
  5. If Windows asks about network access, allow it on your trusted Private network when you want another device to connect. Internet/public-network access is unnecessary for local testing.

3. Create your test PIN

In the browser, enter a shared PIN with 6–12 numbers, repeat it, and select Create PIN & continue. This is a numeric PIN, not a password containing letters. Create it on this host computer first.

4. Try a small test service

  1. Open Equipment. Add a test microphone, IEM pack, and stage-box port (for example, S1a2).
  2. Open Musicians → Add musician. Add a test name and optional photo. Drag/zoom the crop into position.
  3. Open Service lineup, add the musician, choose their roles and assignments, then Publish musician.
  4. In the control window click Backstage display. Confirm the published musician appears.
  5. Change an assignment and save a draft. It should stay unchanged backstage until you publish the update.
  6. Try Setup and Service modes. Setup uses flexible cards; Service uses a single photo row. Hide fixed drum inputs using the assignment checkboxes.

Planning Center is optional. Only connect a church-approved Personal Access Token under Display & connections. The app reads Planning Center; it does not write changes there.

5. Everyday use

  • Double-click the Backstage desktop shortcut to start.
  • Keep the small control window open; minimizing it is fine. The browser can be closed and reopened.
  • Stop app stops the host. Start app starts it again. Closing the control window asks before stopping it.
  • This Windows preview does not start automatically when you sign in. Open the shortcut each time.
  • To test from another device on the same network, use an address shown beside On the same network in the control window. Add /display for backstage or /overlay for ProPresenter. If several addresses are shown, use the Wi-Fi/Ethernet address for the shared network, not a VPN.
  • For ProPresenter, size a web-page fill to the bottom strip and use http://HOST-IP:3100/overlay.

Your data and updates

The app is installed in %LOCALAPPDATA%\Backstage\app. Your data is kept separately in %LOCALAPPDATA%\Backstage\data. Click Open data folder to find it.

Use Display & connections → Export backup before updating. The export includes profiles, photos, equipment and services, but excludes the PIN and Planning Center credentials. For a complete private copy, stop the app, then copy the whole data folder somewhere secure.

To update, close the Backstage control window and run the new installer. It keeps the separate data folder. To remove this preview, close it, delete the desktop/Start shortcuts and the app folder. Keep the data folder unless you intend to erase your setup.

If something does not work

What you seeWhat to do
Port 3100 already in useClose the other Backstage host on this computer, then try again. The installer does not stop another app for you.
Browser cannot connectCheck that the control window says Running. Use Open FOH. If you stopped the app, start it again.
Another device cannot connectUse the host’s network address, not 127.0.0.1. Check that both devices use the same trusted network and Windows allows private-network access.
Host cannot startOpen the data folder and send James host.log after checking it for information you do not want shared. Do not send the database or credentials key in a public issue.
Installer blocked by company policyAsk the administrator. This preview does not have a purchased code-signing certificate.

Finding the right network link

After unlocking FOH, look under Church network at the bottom of the sidebar. The host’s current IP and app port are shown with a copy button. Open Network addresses for display and overlay links. Share the app link (normally port 3100), not the local development preview on port 5173. Addresses refresh when the host’s network changes.

Importing a backup

  1. Open Display & connections → Import backup and choose a Backstage JSON export (up to 100 MB).
  2. Review the current and backup counts. The preview also names the service that will appear backstage.
  3. Check Replace the current saved setup and live lineup with this backup, then click Replace setup from backup. Do this outside a live service.
  4. Your current host PIN and Planning Center connection stay in place. The imported setup replaces profiles, photos, inventory, fixed setups, services and the live lineup.
  5. After success, download the offered safety backup of the previous setup and keep it somewhere private. Import that file to undo the restore. A copy also stays under backups inside the host data folder.

If the app says the setup changed after the preview, choose the file again and review the new counts before restoring. Import replaces data; it does not merge two setups.

Checking for new versions

  1. In Backstage, open Display & connections → App updates.
  2. Updates are ready to use without a GitHub account or token.
  3. The host checks at startup and every six hours. You can also click Check for updates. Preview installations include newer previews; stable installations check stable releases.
  4. When an update appears, download a data backup, then choose Download verified update. The app chooses the host’s Windows or Pi installer and checks its SHA-256 before supplying it.
  5. Close the Backstage control window. Open the downloaded .exe installer and install it as before. The app restarts and retains your data. Do this outside a live service.

You can also use Browse public downloads and install the new package manually. The app does not automatically run an installer or restart during a service. If an older version asks for a GitHub token, install this public package once to switch to account-free updates. Your saved data is retained.
